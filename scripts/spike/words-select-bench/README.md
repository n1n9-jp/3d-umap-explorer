# scripts/spike/words-select-bench

単語の文字（`src/text/`）の「選び直し 1 回の時間」と、点ごとの倍率の属性（`instanceDotScale`）の「GPU への転送量」を測るスクリプトです（スパイク）。アプリ本体には組み込みません。

7 万点の単語のデータセットで、単語の周りの丸い点を小さくする処理（`src/text/clearance.ts`）が、選び直し（カメラが動いている間は毎秒 10 回）ごとに全点を画面へ投影していたこと、不透明度が変わっている間は毎フレーム倍率の属性の全体（7 万点で 280 KB）を GPU へ送っていたことの、修正の前後を比べます。

## 手順

```sh
node scripts/spike/switch-stall/make-synth.cjs --out <dataDir>   # 合成データ（MNIST を 7 回複製して雑音を加えた 7 万点。単語は「ラベル-番号」の仮の文字列）。約 1 分
npm run build
node scripts/spike/words-select-bench/measure.cjs --root . --data <dataDir> --label after --out after.json
# 修正の前は、前のコミットのチェックアウト（git worktree add <dir> <commit> のあと、node_modules を結び、npm run build）で
node scripts/spike/words-select-bench/measure.cjs --root <前のチェックアウト> --data <dataDir> --label before --out before.json
```

内部の視点（MNIST の最も密なクラスタの内部）から、視線を 1 フレームごとに約 1.7 度（0.03 ラジアン）回して 24 フレーム続け、毎フレーム単語を選び直させます（約 95 語が表示され、丸い点を小さくした点が約 2 600〜13 300 個）。選び直しごとの時間は `WordLabels.getState().select`、転送量は WebGL の `bufferSubData` を包んで、点ごとの倍率の属性のバッファ（`bufferData` の大きさが 点の数 × 4 バイト）への呼び出しを数えます（修正の前後を同じ方法で測れます）。

## 結果（この実行環境、4 vCPU・GPU なし・ヘッドレス Chromium のソフトウェア描画。7 万点・960×600）

選び直し 1 回の時間（24 回。単語の選び方と、単語の周りの丸い点の探索の合計。ミリ秒）:

| | 修正の前 | 修正の後 |
|---|---|---|
| 平均 | 14.2 | **5.2** |
| 中央値 | 15.3 | **5.1** |
| 最大 | 18.5 | 10.8 |
| 丸い点の探索の分（平均。修正の後だけ出力） | — | 3.9 |

倍率の属性の GPU への転送（描画したフレームごと。ソフトウェア描画では 1 フレームが長いので、1 回の選び直しの切り替え 0.2 秒が 2 フレームほどで終わり、描画 194 フレームのうち 48 フレームで転送が起きます）:

| | 修正の前 | 修正の後 |
|---|---|---|
| 転送のあったフレームの数 | 48 / 194 | 48 / 194 |
| 1 フレームあたりの平均（全フレーム） | 69.3 KB | **55.1 KB** |
| 転送のあったフレームの平均 | 280 KB（毎回全体） | 約 224 KB |
| 最大 | 280 KB | 280 KB（散らばった点が全体にわたるとき） |
| `bufferSubData` の回数（平均・最大） | 0.25・1 | 8.0・176 |

この計測は、カメラを回し続ける最悪に近い場面です。選び直しのたびに、丸い点を小さくする点の約 1 万個がほぼ入れ替わり、しかも点の番号は空間の並びと無関係なので、変わった点が属性の全体に散らばります。そのため転送量の減りは約 2 割にとどまります。カメラが止まっているときや、少数の単語の出入りだけのときは、変わった点の範囲（数百バイト〜数 KB）だけを送ります（`src/render/dotScales.test.ts`）。

## 丸い点の探索だけの計測（Node。同じ 7 万点・1280×800、時間はミリ秒）

選び直しの丸い点の探索（`pointsNearRects`）だけの時間です。`src/text/clearance.bench.test.ts`（`SYNTH` を設定したときだけ動く計測。通常のテストでは何もしない）が、MNIST の縁・内部・内部の密な場所の 3 視点で、カメラに近い単語を選んだ結果の矩形（先頭から 5・20・全部）について、3 つの方式の結果が一致することを確かめて、時間（10 回の平均）を出します。

```sh
SYNTH=<合成データ> npx vitest run src/text/clearance.bench.test.ts --disableConsoleIntercept
```

| 表示中の単語の数 | 小さくする点の数 | 修正の前の方式（全点を投影し、点ごとに全矩形を総当たり） | 全点＋タイルの格子 | 空間索引の木＋タイルの格子（採用） |
|---|---|---|---|---|
| 124〜151 語 | 13 029〜14 383 | 13.4〜22.0 | 4.5〜4.6 | 4.0〜4.8 |
| 20 語 | 1 277〜3 867 | 5.6〜6.7 | 2.7〜3.1 | 0.7〜1.3 |
| 5 語 | 112〜727 | 3.2〜4.5 | 1.9〜3.1 | 0.16〜0.40 |

主な効果は、点ごとに全矩形を総当たりで調べていたことの解消です。矩形を 16 ピクセルのタイルの格子に登録して、点ごとに、その画面上のタイルの矩形だけを調べます（点を投影するときの、点ごとのオブジェクトも作りません）。全点を調べる場合でも 3〜5 倍速くなります。空間索引の木は、単語が少ないとき（矩形が画面の一部だけを覆うとき）に、カメラの後ろと矩形のない画面の領域を丸ごと飛ばして、全点の場合の 3〜10 倍速くします。単語が画面の広い範囲を覆うとき（調べる点が全体の半分に及ぶとき）は、全点の場合と同じ程度です。
