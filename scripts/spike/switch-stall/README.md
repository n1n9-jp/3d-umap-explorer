# scripts/spike/switch-stall

ブラウザ内の UMAP の再計算で、計算した座標を表示へ切り替えるときの、メインスレッドの停止時間を測るスクリプトです（スパイク）。アプリ本体には組み込みません。

切り替えでは、空間の構造（全体の範囲・密度・主成分軸・ラベルごとのまとまり）と空間索引を作り直します。修正の前は、これをメインスレッドで行っていました（空間索引の構築、全点の 8 近傍の検索、ラベルごとの代表点 medoid の総当たり。点数の 2 乗に比例）。修正の後は、別の Worker（`src/compute/structureWorker.ts`）で、点を動かしている間に計算し、作った空間索引も表示へ渡します。

## 手順

```sh
node scripts/spike/switch-stall/make-synth.cjs --out <dataDir>   # 合成データ（MNIST を 7 回複製して雑音を加えた 7 万点）。約 1 分
npm run build
node scripts/spike/switch-stall/measure.cjs --root . --data <dataDir> --label after --out after.json
# 修正の前の測定は、前のコミットのチェックアウト（ビルド済み）で。同じ名前の performance.measure を足して測る（measure.cjs の冒頭の説明）
node scripts/spike/switch-stall/measure.cjs --root <前のチェックアウト> --data <dataDir> --label before --out before.json
```

`measure.cjs` は、チェックアウトの `dist/data/synth/` へ合成データをコピーして開き、UMAP（近傍数 15・min_dist 0.1・種 42・200 エポック）を最後まで計算させます（7 万点で 1〜2 分）。

## 合成データ

MNIST 1 万点の 3 次元座標とラベルを 7 回複製し、複製ごとに等方ガウス雑音（標準偏差 0.01。座標の絶対値の最大は 1）を加えた 7 万点です（最初の複製は雑音なし）。ラベルは 10 種類で 1 種類あたり約 7000 点です。kNN グラフ（k=50）は、この 3 次元座標での厳密な近傍です（UMAP を最後まで走らせるための入力で、結果の質を測るものではありません）。manifest の bounds・density・overview・clusters は MNIST のものを流用します。点ごとの文字列（`kind` を text にするため）は `<ラベル>-<番号>` です。

## 結果（この実行環境、4 vCPU・GPU なし・ヘッドレス Chromium のソフトウェア描画）

7 万点・ラベル 10 種類・近傍数 15・200 エポックの 1 回の計算の、切り替えでメインスレッドが 1 つのタスクで止まった時間（`performance.measure`）：

| | 修正の前 | 修正の後 |
|---|---|---|
| 空間の構造と空間索引の構築（`umap:build`） | **12 561 ミリ秒** | **2〜4 ミリ秒**（結果の取り込みだけ） |
| 表示の作り直し（`umap:replaceView`。修正の前は空間索引の構築を含む） | 66 ミリ秒 | 44〜47 ミリ秒 |
| 続けて動く 2 つの合計（切り替えで 1 つのタスクが止まる時間の最大） | **12 627 ミリ秒** | **46〜51 ミリ秒** |
| 結果の位置合わせ（`umap:align`） | 18 ミリ秒 | 18〜23 ミリ秒 |
| Worker での構造の計算（起動から結果が届くまで） | — | 6.2 秒（点を動かしている間に進む。描画と Worker が同じ 4 コアを使っている環境の値。何も動いていない Node では、同じ計算が約 0.7 秒） |

`longtask` では、修正の前に 14.3 秒のタスクが 1 つ出ます（切り替えの時間帯の最長）。修正の後の切り替えの最長は 1.66 秒で、これは 7 万点の 1 フレームの描画（ソフトウェア描画。計算中も同じ長さのタスクが並ぶ）で、切り替えによる停止ではありません。

出力の例は `measure.cjs` の標準出力（JSON）です。
